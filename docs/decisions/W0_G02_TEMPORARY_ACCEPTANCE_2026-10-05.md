## หลักฐานการอนุมัติจากเจ้าของ

หลังอ่านข้อเสนอ G-02 และคำอธิบายข้อจำกัด เจ้าของยืนยันในบทสนทนาว่า:

> โอเค ผมให้การยอมรับ อนุมัติตามข้อเสนอ ภานใตเขอบเขตที่กำหนด แงะเป็นเพียงการชั่วคราวเท่านั้น และผมอาจพิจรณา จัดการ model ใหม่ หรือ สังกัดใหม่ หรือความพร้อมทางการขอสิทธิในการเข้าถึงการใช้ key API ณ เวลานั้น  ก็จะทำการ ปลดอนุมัติข้อเสนอนี้ เพื่อให้ระบบทำงานได้ตาม RODEMAP

ข้อความข้างต้นเก็บตามต้นฉบับ รวมการสะกดเดิม คำอธิบายต่อไปนี้สรุปขอบเขตโดยไม่ขยายอำนาจจากคำยืนยัน ไม่ได้ใช้ภาพลายเซ็นแทนข้อความอนุมัติ

## ขอบเขตที่ยอมรับชั่วคราว

1. เดโม local ด้วยบัญชีและข้อมูลจำลองสำหรับ MVP/Portfolio เดิมอาจดำเนินต่อ แม้ Gemini ไม่พร้อมสร้าง Clinical Summary บางครั้ง เมื่อไม่สำเร็จต้องแสดง summary unavailable และข้อมูลต้นทางตามสิทธิ์ พร้อม disclaimer และ human review ตามเดิม
2. ยอมรับช่องว่างของหลักฐานสาเหตุ failed collector ครั้งเก่า ซึ่ง metadata ที่เก็บไว้ไม่พอระบุสาเหตุแน่นอน เก็บผลเดิมเป็น FAIL และไม่อ้างว่าเกิดจาก key format หรือ HTTP 503 โดยไม่มีหลักฐาน
3. ข้อจำกัดนี้เป็นการชั่วคราวและเพิกถอนได้ ไม่มีการอนุมัติถาวร ไม่มีวันสิ้นสุดตามปฏิทินที่เจ้าของระบุ

## หลักฐานที่ใช้พิจารณาและสิ่งที่ยังไม่ยืนยัน

- EC-011: standalone synthetic calls ได้ทั้ง 200/STOP/3 PASS และ 503/UNAVAILABLE; ไม่ใช่ full collector
- EC-012: full live collector ที่ 3f4b5cf ผ่าน 14 gates แล้ว Gemini 503 FAIL/exit 1 พร้อม safe diagnostics; typecheck/build ไม่ถึงในรอบนั้น
- EC-013: non-live collector ที่ b51d55d ผ่าน 16 gates รวม typecheck/build; source ก่อน/หลัง clean และตรงกัน ไม่มี live generation ในรอบนี้
- Mocked endpoint regression ยืนยัน assignment-scoped unavailable fallback และ unassigned denial; ไม่ใช่ live UI 503 coverage หรือ clinical validation
- ยังไม่รับรอง uptime, ความถูกต้องของทุก summary, สาเหตุภายใน Google หรือผล full live collector ผ่านครบ 17 gates

## ขอบเขตความปลอดภัยและสถานะ

- **G-02 / RISK-001 / RISK-007 และ W0 ยังคง OPEN** การยอมรับเฉพาะข้อจำกัดเดโมไม่ปิดความเสี่ยงหรือเปลี่ยนข้อกำหนดเดิม
- คง model choice, auth/assignment/revocation, source fallback, disclaimer และ human authority ไม่เพิ่ม retry หรือเปลี่ยน model เพื่อทำให้ผลทดสอบผ่าน
- ไม่ยอมรับ defect จริงด้าน privacy, authorization หรือ safety หากพบ boundary/fallback ผิดข้อกำหนด ต้องแก้ก่อนดำเนินส่วนที่ได้รับผลกระทบ
- ใช้เฉพาะ local synthetic demo ไม่ครอบคลุมผู้ป่วยจริง ระบบสาธารณะ หรือการตัดสินใจทางคลินิก
- G-01/RISK-003 OPEN และ G-06 limited acceptance คงตามคำตัดสินเดิม ไม่อนุมัติ G-03/G-04/G-05, W0 closure, baseline/tag/freeze หรือ main merge

## เงื่อนไขทบทวนและถอนการอนุมัติ

เจ้าของอาจพิจารณาโมเดลใหม่ ผู้ให้บริการ/สังกัดใหม่ หรือความพร้อมในการขอสิทธิ์ API key และจะถอนการอนุมัติชั่วคราวนี้ ณ การพิจารณานั้น เพื่อดำเนินระบบตาม Roadmap การอนุมัตินี้ไม่ได้เลือกโมเดลหรือผู้ให้บริการใหม่ และไม่ได้สั่งซื้อเครดิตหรือขอสิทธิ์ API โดยอัตโนมัติ

เมื่อถึงการพิจารณา ให้บันทึกคำตัดสินถอน/แทนที่โดยอ้าง HD-W0-G02-TEMP-2026-10-05 เก็บประวัติเดิม แล้วตรวจ model/provider/access และพฤติกรรมบน source/commit จริงตาม Roadmap ก่อนอ้างว่า verified ไม่ยกผลของรุ่นเก่าไปใช้รับรองรุ่นใหม่โดยตรง

ทบทวนเมื่อ provider failure เกิดซ้ำ, source/model/intended use เปลี่ยน, fallback/boundary ผิดข้อกำหนด หรือก่อนใช้ข้อมูลจริง/เปิดภายนอก งานติดตามเดิมของ RISK-001/007 คงอยู่ หากเกิด defect จริง การยอมรับชั่วคราวไม่อนุญาตให้ข้ามการแก้ไข
